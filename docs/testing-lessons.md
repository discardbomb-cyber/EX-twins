# Ошибки проверок и принятые решения

Каждая ошибка сборки, теста или проверки сохраняется. Перед повторным запуском оставь исходный лог с уникальным именем; не перезаписывай неудачный прогон. В этот журнал добавь дату, ветку/HEAD, команду, симптом, установленную причину, исправление, результат повторной проверки и правило на будущее. Неизвестную причину помечай как гипотезу. Повторы связывай с существующей записью, перечисляя новые прогоны.

Полные логи храни локально в `work/test-runs/<дата-время>-<задача>.log`, тяжёлые дампы — на D:. В Git сохраняй этот краткий журнал; не публикуй секреты, токены и частные переписки. После исправления переноси устойчивый вывод в docs/development.md или AGENTS.md. Не скрывай ошибки отключением проверок и не обновляй эталоны без объяснения изменения поведения.

## TEST-001 — отсутствующий артефакт Mekanism

- Дата: 02.10.2026; ветка codex/mekanism-recipes от main 3744118.
- Команда: `./gradlew.bat build runGameTestServer --console=plain`.
- Ошибка: `Could not find mekanism:Mekanism:1.21.1-10.7.15.80` в testRuntimeClasspath.
- Причина: пример версии в README Mekanism не соответствует опубликованному артефакту. Maven metadata содержит 1.21.1-10.7.15.81.
- Исправление: версия заменена на 10.7.15.81. Следующий прогон разрешил зависимость и дошёл до verifyContracts.
- Вывод: перед закреплением зависимости проверять Maven metadata/POM. Первоначальный полный лог был перезаписан до введения этого правила; диагностический фрагмент сохранён здесь, не заявляем наличие полного лога.

## TEST-002 — намеренное изменение контрактов ресурсов

- Дата: 02.10.2026; та же ветка. Команда: `build runGameTestServer`.
- Ошибка: `37 contract differences; resources and goldens are frozen` в verifyContracts.
- Причина: новая обязательная цепочка Mekanism меняет 18 рецептов, 18 advancement-условий их открытия и neoforge.mods.toml.
- Исправление: пересчитать только эти 37 записей resources.sha256; остальные ресурсы, литералы и golden masters не менять. Это согласованное изменение игрового поведения, а не обход теста.
- Повторная проверка: verifyContracts прошёл; все 95 GameTests прошли, но последующая Gradle-проверка числа тестов выявила TEST-003. Лог неудачного прогона: `work/test-runs/2026-10-02-mekanism-contract-failure.log` в исходном checkout.
- Вывод: рецепты входят в замороженный контракт; при изменении прогрессии нужен ограниченный пересмотр эталона с объяснением.

## ENV-001 — валидатор навыков без PyYAML

- Дата: 02.10.2026; штатный `quick_validate.py` не запустился из-за `ModuleNotFoundError: yaml`.
- Исправление: PyYAML установлен только в локальный `work/skill-validation-deps`, задан PYTHONPATH. Оба навыка прошли штатную проверку: `Skill is valid!`.
- Вывод: отсутствие библиотеки валидатора — проблема среды, а не ошибка содержимого навыка. Сетевая попытка внутри песочницы была запрещена; установка выполнена после разрешения вне неё.

## NET-001 — armageddon_blast отсутствует на сервере

- Дата сообщения автора: 02.10.2026; релизная база main 3744118.
- Симптом: клиент отключается с сообщением, что `relics_addon:armageddon_blast` требуется клиенту, но отсутствует на сервере.
- Причина подтверждена diff: `playToClient` зарегистрирован внутри `FMLEnvironment.dist.isClient()`.
- Исправление подготовлено в EX-twins-merge: безусловная регистрация payload, клиентская реализация внутри handler lambda, импорт domain.hive.HiveType.
- Повторная проверка: `hotfix-run02` — BUILD SUCCESSFUL, все 95 обязательных GameTests прошли. Коммит `433317a22e7456feba5ffd66f2735507fed7ecf1` отправлен в main; JAR v1.0.0 заменён, SHA-256 совпал с GitHub: `d2f95a235bfc695ccb5b50b994db63516569c1f65670cf0a235feff09017530c`.
- Вывод: сетевой протокол регистрируется одинаково на клиенте и сервере; проверять серверную регистрацию отдельно от клиентского запуска.

## TEST-003 — число GameTests в контрольном шаге Gradle

- Дата: 02.10.2026; codex/mekanism-recipes. Лог: `work/test-runs/2026-10-02-mekanism-run03.log`.
- Результат игры: `All 95 required tests passed`. Gradle ожидал строку про 94 теста и завершил задачу ошибкой.
- Причина: после добавления RecipeGameTests не обновлён строгий счётчик в build.gradle.
- Исправление: увеличить ожидаемое число ровно на добавленные обязательные тесты; сохранять проверку свежести лога и полного количества, не заменять её произвольным совпадением «tests passed».
- Повторный результат: mekanism-run04 — BUILD SUCCESSFUL, все 96 обязательных GameTests прошли (включая сетевую регрессию). Вывод: новый GameTest требует синхронного обновления контрольного счётчика.

## ENV-002 — первый запуск GameTest-мира

- Дата: 02.10.2026; тот же run03. Minecraft вывел `Failed to load properties from file: server.properties`.
- Причина: новый run-gametest ещё не имел server.properties; сервер создал его и завершил все 95 тестов успешно.
- Вывод: отличать первичную генерацию файла от падения сервера; сохранять сообщение и проверять фактический итог. Нельзя считать любую ERROR-строку доказательством провала всех тестов.

## TEST-004 — клиентский класс в common bytecode

- Дата: 02.10.2026; main / сетевой hotfix. Лог: `work/test-runs/2026-10-02-hotfix-run01.log`.
- Ошибка: verifyArchitecture обнаружил одну зависимость класса после восстановления прямого вызова ArmageddonVisual из common payload.
- Причина: даже вызов внутри lambda оставляет ссылку в bytecode, запрещённую архитектурой после S6.
- Исправление: сохранить существующий отложенный reflective handler; убрать только client-only условие регистрации. Эталон литералов сохранён. Серверный GameTest проверяет реальные зарегистрированные кодеки Fire и Blast.
- Повторный результат: hotfix-run02 — BUILD SUCCESSFUL, все 95 тестов прошли. Вывод: общая регистрация обязательна на обеих сторонах, но её callback также должен соблюдать границы архитектуры.

## MCP-001 — OAuth resource mismatch у ElevenLabs

- Дата: 02.10.2026. `codex mcp login ElevenLabsAudio` с публичным адресом `https://api.elevenlabs.io/v1/mcp` отклонён: metadata указывает ресурс `https://api.us.elevenlabs.io/v1/mcp`.
- Исправление: конфиг обоих клиентов переведён на канонический адрес, заявленный самим сервером. Проверку resource не отключали.
- Повторный результат: CLI сформировал OAuth-ссылку. Затем автор отменил установку ElevenLabs: вход остановлен, записи удалены из обоих клиентов. Сохранённых OAuth-данных CLI не обнаружил.
- Вывод: сверять URL protected resource metadata; не обходить проверку адреса и не сохранять ключи в репозитории.
